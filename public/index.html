💡 为什么推荐直接托管在 GitHub？
1. 完全免维护、0 费用：无需购买云服务器或在本地常开 NAS / 电脑。
2. 全自动定时每日更新：GitHub Actions 每天凌晨自动拉取 Z2M 官方最新 npm 库，提取新设备转换器。
3. 全球高速 HTTPS CDN 分发：GitHub Pages 提供全球 CDN 和自动 SSL 证书，ESP32-C3 可全球秒速同步！

🛠️ 3 步在 GitHub 开启自动同步服务：

1 新建 GitHub 仓库并上传代码

将本套件解压后的 z2m_manifest_server/ 目录内容上传至您的 GitHub 仓库（例如 https://github.com/your-name/my-z2m-manifest）。

# 仓库根目录应包含：
├── .github/workflows/z2m_binary_pipeline.yml  # v10 自动工作流
├── tools/                                     # IR 提取、编译器、校验器
├── tests/                                     # 自包含 matcher 差分门禁
├── build_ir_frozen/                           # 当前已验证冻结 IR
└── tutorial.html

2 在仓库中开启 GitHub Pages 权限

  1. 进入您的 GitHub 仓库页面，点击 Settings（设置）-> Pages。
  2. 在 Build and deployment 下的 Source（来源）下拉菜单中选择 GitHub Actions。

3 触发首次运行并获取同步 URL

  1. 点击仓库顶部的 Actions 标签页 -> 选择 Z2M Binary Bundle v10 CI/CD Pipeline。
  2. 点击右侧 Run workflow（手动运行）按钮。
  3. 运行完成后，GitHub Pages 会自动生成您的专属 HTTPS 同步链接：
    https://<你的用户名>.github.io/<仓库名>/manifest.json
🎉 绑定到 ESP32 网关：
在终端向网关执行一条命令（或在网关网页后台粘贴该 URL）： 
curl -X POST "http://192.168.2.249/api/z2m/sync?manifest=https://<你的用户名>.github.io/<仓库名>/manifest.json"
此后，无论何时 Z2M 官方发布新设备，网关都会在 24 小时内自动无缝静默拉取更新。
🏗️ 架构与工作原理 Architecture

官方 zigbee-herdsman-converters (Z2M) 当前包含 4500+ 款 Zigbee 设备定义，但它们由 JavaScript/TypeScript 编写，并包含大量复杂的 JS 执行函数（如 fromZigbee、toZigbee、configure 等）。

⚠️ 为什么不能在 ESP32 上直接运行 Z2M JS 文件？
ESP32-C3 的 RAM 仅有约 320KB（扣除 Wi-Fi、BLE、HomeKit 后可用仅 ~250KB），若嵌入 JavaScript 引擎执行 70MB+ 的 Z2M 脚本会导致内存直接溢出（OOM Panic）。

因此，本项目采用了业界创新的 “云端/PC 预编译抽取 + ESP32 声明式极速解析” 架构：

┌──────────────────────────────────────┐ │ GitHub Actions (每天定时自动拉取) │ │ - 官方 Z2M 库 4500+ 设备 │ └──────────────────┬───────────────────┘ │ ▼ [tools/build_candidate.py] ┌────────────────────────────────────────────────────────┐ │ GitHub Pages 全球 HTTPS CDN / 本地 Docker 输出端: │ │ • z2m_manifest.json (v10 元数据、SHA256、设备计数) │ │ • z2m_bundle.bin (Z2MB v10 二进制声明式规则包) │ └──────────────────┬─────────────────────────────────────┘ │ HTTPS (GET z2m_manifest.json) ▼ ┌────────────────────────────────────────────────────────┐ │ ESP32-S3 网关 (ZigbeeSync 引擎): │ │ 1. 校验 Z2MB v10、布局边界与 SHA-256 完整性 │ │ 2. 原子写入 LittleFS (/z2m_bundle.bin) │ │ 3. 动态加载至 ConverterEngine 与 HomeKit / MQTT 桥接 │ └────────────────────────────────────────────────────────┘
⚡ 自建/局域网部署方式 Local Deploy

方案 A：Docker 一键部署

适用于 NAS、群晖、树莓派、Linux 服务器或本地电脑。

# 1. 进入服务目录
cd tools/z2m_manifest_server

# 2. 一键启动容器
docker-compose up -d

# 服务已在 http://你的IP:8088 启动！

方案 B：Python 零依赖极速启动

无需安装任何第三方库，内置 Python 3 原生 HTTP 服务器。

# 1. 进入服务目录
cd tools/z2m_manifest_server

# 2. 启动服务 (默认端口 8088)
python3 server.py

# 访问 http://localhost:8088/manifest.json

方案 C：Nginx / Caddy 静态托管

先完成候选构建与校验，再把 public/ 作为静态目录托管。

# 构建、验证并提升正式 v10 发布物
python3 tools/build_candidate.py --promote

# Nginx 配置示例：
location /z2m/ {
    alias /var/www/z2m/;
    add_header Access-Control-Allow-Origin *;
}
🛠️ 编写自定义私有 Zigbee 设备定义 Custom Converter
当前 v10 自动流水线以官方 zigbee-herdsman-converters 为唯一来源，不会自动合并旧版 custom_devices.json。私有设备需要后续单独扩展并经过同一套全量门禁后发布。

下面是 v10 声明式 IR 的字段格式示例，仅供扩展开发参考：

[
  {
    "model": "MY_CUSTOM_TEMP_SENSOR",
    "models": ["MY_CUSTOM_TEMP_SENSOR", "DIY_TH_V1"],
    "vendor": "MySmartHome",
    "description": "DIY 电池供电温湿度传感器",
    "matter_type": "temp_sensor",
    "fromZigbee": [
      {
        "cluster": "0x0402",
        "attr": "0x0000",
        "type": "int16",
        "multiply": 0.01,
        "expose_to": "temperature"
      },
      {
        "cluster": "0x0405",
        "attr": "0x0000",
        "type": "uint16",
        "multiply": 0.01,
        "expose_to": "humidity"
      },
      {
        "cluster": "0x0001",
        "attr": "0x0021",
        "type": "uint8",
        "multiply": 0.5,
        "expose_to": "battery"
      }
    ],
    "toZigbee": []
  }
]

常用 ZCL Cluster 与属性速查表

  • 0x0006 / 0x0000 (bool): 开关状态 state (ON / OFF)
  • 0x0008 / 0x0000 (uint8): 亮度等级 brightness (0~254)
  • 0x0402 / 0x0000 (int16, multiply: 0.01): 摄氏温度 temperature
  • 0x0405 / 0x0000 (uint16, multiply: 0.01): 相对湿度 humidity
  • 0x0406 / 0x0000 (uint8): 人体移动/感应 occupancy
  • 0x0500 / 0x0002 (uint16): 门磁/水浸报警 contact
  • 0x0001 / 0x0021 (uint8, multiply: 0.5): 电池剩余百分比 battery

方法 2：自动周期刷新机制

一旦设置了 Manifest URL，ESP32 网关将保存该地址至 NVS，并满足以下特性：

  • 每 24 小时自动静默检查更新：仅在版本或 SHA256 哈希变动时拉取，不浪费 Flash 寿命与网络带宽。
  • 断电记忆：网关重启后自动维持最新规则库。
  • 断网降级：无网络时自动使用内置烘焙的转换器库，保证核心设备离线可用。

❓ 常见问题与排查 (FAQ) Troubleshooting
  • Q: ESP32 支持直接从 GitHub Pages HTTPS 地址下载吗？
    A: 支持 HTTPS 下载。当前固件使用 WiFiClientSecure::setInsecure()，传输加密但不验证证书链；生产环境应使用可信域名和 Bundle 哈希校验。
  • Q: 提示 SHA256 hash mismatch？
    A: 说明下载的文件哈希与 manifest.json 中的记录不一致。GitHub Actions 会在每次构建时自动重新计算准确的 SHA256。
  • Q: 官方收录新设备后需要改版本号吗？
    A: 不需要手动改。定时任务会查询 npm 最新版，自动锁定版本、构建候选、跑全量门禁；只有二进制变化才提交并发版。
